Massa de dados de teste com Python e Faker (pt_BR)

Gere milhares de clientes e empresas fictícios, com CPF e CNPJ válidos, em CSV ou direto no banco, com resultados reproduzíveis entre execuções.

Por Fernando Parmezani · Publicado em 22 de novembro de 2026

Por que usar o Faker

O Faker é uma biblioteca Python que gera dados falsos realistas. Com o locale pt_BR, ele cria nomes, CPFs, CNPJs, endereços, CEPs e telefones no padrão brasileiro. É a forma mais rápida de popular um banco de homologação sem usar dados de pessoas reais, o que também resolve boa parte das preocupações com a LGPD (veja Dados de teste e LGPD).

Gerando clientes em CSV

Pontos importantes do script:

  • Faker.seed(42) torna o resultado reproduzível: a mesma semente gera os mesmos dados em toda execução. Isso ajuda a reproduzir um bug encontrado com um dado específico.
  • fake.unique garante que CPF e e-mail não se repetem, essencial quando a coluna tem restrição de unicidade.
  • fake.cpf() gera CPFs com dígitos verificadores corretos e com máscara (000.000.000-00).
  • Os e-mails usam domínios reservados para exemplos (como example.org), que não entregam mensagens a ninguém. Assim, um teste que dispara e-mails não incomoda pessoas reais.

Rodando o script, cada linha sai assim:

Brenda Alves,721.175.500-88,mirellapereira@example.org,+55 82 98637-9402,54235-116,Fogaça,MS,1986-12-22

Limitações que você precisa conhecer

  • Cidades e bairros são inventados. O Faker combina pedaços de nomes e pode gerar algo como "Fogaça". Se o sistema valida cidade contra uma tabela do IBGE, sorteie a cidade dessa tabela.
  • CEP, cidade e UF não combinam entre si. Cada campo é sorteado separadamente. Para testes de frete ou de busca por CEP, use uma lista de endereços reais de exemplo.
  • CNPJ só no formato numérico. Para o alfanumérico, use o Gerador de CNPJ ou implemente o cálculo com as funções da página.
  • Não há CNH, PIS, Título de Eleitor nem RENAVAM no Faker. Use os geradores do 4DevTools ou as funções de cálculo publicadas em cada um.

Boas práticas

  • Versione o script de seed junto com o projeto, para que qualquer pessoa do time recrie o banco de homologação.
  • Gere também casos extremos: nomes com acentos e apóstrofos (D'Ávila), sobrenomes longos e CPFs que começam com zero.
  • Mantenha a semente fixa nos testes automatizados e varie a semente em testes exploratórios.
